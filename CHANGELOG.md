# Changelog

All notable changes to Oikos are recorded here, most recent first. Also viewable in-app under **Release Notes**.

## 2026-08-11

### Added
- **Cash Flow Forecast → Horizon gains an EOY option** — projects through Dec 31 of the current year, recalculated each time you click it rather than a fixed day count.
- **Cash Flow Forecast → Recurring window gains a YTD checkbox** — uses every complete calendar month so far this year instead of the 2–6 month slider, without discarding your manual slider position (unchecking restores it). The backend's recurring-window cap was raised from 6 to 12 months to accommodate this — previously anything above 6 was silently clamped down.

## 2026-08-10

### Added
- **Numeric columns in ag-Grid tables now offer numeric filter operators** (equals, greater than, less than, in range, etc.) instead of the text-filter defaults (Contains, Begins with, ...) — applied wherever a column already used the numeric type: Securities Analysis, Market Data, Static Data, Security Detail, and Investments' Holdings tab. Grids using infinite scroll (Cash Register, Investments → Transactions) don't have column filters at all — client-side filtering doesn't make sense there — so they're unaffected. The filter is now set explicitly on each numeric column rather than only through the shared column-type default — the type-only approach worked for most columns but silently fell back to the text filter on ones with a lot of blank/null values in the loaded data (Sharpe, Quality, P/E, Market Cap, and others), since ag-Grid infers a column's filter from sampled values when it isn't set directly.
- **Securities Analysis → Portfolio Action Signals gains Volatility columns** (1M/3M/1Y/YTD annualized, same figures as the dedicated Volatility tab) — 1Y shown by default, the others available via the Columns menu — so volatility can be sorted/filtered alongside signals and P&L instead of only in its own separate high/low list.
- **Portfolio Action Signals now remembers applied column filters** across navigation (e.g. clicking through to a Security Detail page and back), the same way column order/width/sort already did — previously any filter you'd applied was silently lost. Also adds a **Clear Filters** button, shown only while a filter is active.

### Fixed
- **Typing into a Portfolio Action Signals column filter closed the filter popup after a moment** — saving the newly-persisted filter on every change re-rendered the component with a freshly-recreated `defaultColDef` object, which ag-Grid treated as a column-config change and reset for, closing whatever filter popup was open mid-keystroke. Given a stable reference instead.
- **Weekly AI Summary reverted to its earlier, more readable format** — a "Here is your weekly summary:" lead-in and a closing numbered list of the week's top 5 transactions (payee, amount, expense/income). A later prompt revision had switched it to a stricter no-list, no-greeting narrative that lost that structure.

## 2026-08-09

### Added
- **Stock split history can now be downloaded from Yahoo Finance**, alongside the existing Download Dividend History — available from Security Detail → Downloads and Market Data → Downloads. Populates the Corporate Actions table with plain Split/Reverse Split reference records (idempotent — re-running skips dates already on record) without touching holdings, exactly like dividend history download doesn't create dividend transactions on its own.
- **Stock split download is now a Scheduled Task** ("Stock Splits" under Tools → System → Scheduled Tasks), running weekly alongside Dividend History. Any genuinely new split it discovers raises a dashboard alert, dismissible the same way as Signal Change alerts.
- **Corporate Actions → editing an existing Split/Reverse Split that has no linked transactions yet** (e.g. one just downloaded from Yahoo) now offers a "Preview affected holdings" step and, on Save, inserts the resulting ShrIn/ShrOut transactions for every account that held the security as of the effective date — labeled "Save & Apply" to make the extra effect clear. Once a split has linked transactions, editing it goes back to updating the record's fields only, same as before. Skips (rather than duplicates) any account that already has an unlinked ShrIn/ShrOut on that exact date — i.e. a split entered manually before this feature existed — flagging it for manual review instead.
- **Tools → Database → "Splits/Reverse Splits Missing Transactions"** — a new diagnostic that finds Split/Reverse Split records with no linked investment transactions (recorded but never applied to holdings) and lets you select and apply them in bulk, same select/confirm/apply pattern as the existing "Fix Missing Transfer Mirrors" tool. Same manually-entered-split detection as above applies here (and to the pre-existing "New Corporate Action" Preview → Execute flow's split handling) — an account already carrying an unlinked ShrIn/ShrOut for that date is left alone rather than double-applied.
- **Security Detail → Investment Transactions → All Transactions, and Investments → Transactions, both gain a Qty Held column** — the running quantity held in that account+security, immediately after each transaction, so a position's history can be read top-to-bottom without cross-referencing Holdings separately. On the Investments page (which mixes every security in an account together) it's computed over each security's full history regardless of the active date-range/action filters, so it always reflects the true holding level at that point in time.
- **Investments → Transactions no longer paginates** — replaced with AG Grid's infinite row model (same change already made to Cash Register): rows stream in as you scroll instead of clicking through numbered pages, and sorting/searching are now pushed server-side so they apply across the whole account instead of just whatever page happened to be loaded. The pinned Balance column (and the page header's fallback balance figure, for accounts with no current holdings value) is now computed server-side over the account's true full history too, fixing a pre-existing bug where it only ever reflected the single most-recently-loaded page of transactions rather than the real running balance.

### Fixed
- **"Save as recurring template" silently did nothing when saving a transfer** (new or edited) — the transaction/transfer itself saved fine, but no template was created. The transaction save logic has five separate paths (new transfer, edited transfer, new/converted installment series, plain transaction); the recurring-template creation was only wired into the plain-transaction path, so both transfer paths skipped it entirely. Now shared across all three transaction-save paths that support it.
- **The Split/Reverse Split "Tools diagnostic" could wrongly flag an account that needed no adjustment at all** — when a position was fully closed via a same-day Sell recorded in pre-split share terms (the split's effective date itself), the diagnostic ignored that closing Sell and treated the pre-split holding as still outstanding, even though it had already been sold that same day — disagreeing with the Corporate Actions "Preview affected holdings" step, which correctly showed nothing to update. Both now agree: a same-day transaction is counted toward the pre-split baseline, same as before this whole feature was built — the separate manually-entered-split check (added alongside it) is what actually guards against double-counting.

## 2026-08-08

### Added
- **Portfolio Analysis → Stock Overlap can now import unregistered fund constituents from Yahoo Finance in one click** — a fund's top-10 holding that isn't already a Securities row (not held directly, never imported) shows an **Import from Yahoo** button instead of plain text; since the exact ticker is already known from the fund's own holdings data, there's no form to fill in — it fetches the security's Yahoo metadata and creates the row directly. Registered symbols (existing or freshly imported) now link through to Security Detail, same as everywhere else in the app.
- **Inv. Performance → P&L and Performance both gain 1Y/3Y/5Y periods**, alongside the existing D/W/M/Q/YTD/All-Time. Kept out of the main P&L query (which already computes six period variants and is live-refetched) to avoid slowing it down for everyone — the long-term figures come from a separate endpoint that only runs when one of those periods is actually selected, roughly a third the cost of the main query since it computes just the one window.

### Fixed
- **Inv. Portfolio's "As of date" control showed on every sub-tab, even ones that ignore it** — Current Holdings, FX Exposure, and Portfolio Analysis all show live data regardless of the selected date, but the control stayed visible and editable there anyway, implying it did something. Now hidden on those three; still shown (and functional) on Graph, Summary, and Detail Analysis, the only ones that actually use it.

## 2026-08-07

### Added
- **Dashboard → the triggered alerts panel has a "Dismiss all Signal Changes" button** next to the header, when there's more than one — batch-acknowledges every currently-listed Signal Change alert in one click instead of dismissing them one by one. Price Alerts (which don't have a per-item dismiss here) are untouched either way.
- **News → the source badge on each item is now its own link**, separate from clicking the row itself (which still opens the article) — a Security badge goes to that security's Security Detail page, an Institution badge opens Static Data → Institutions with that institution's edit modal already open, and a Company badge does the same on the Payees tab. Search-result items with no resolved source aren't linkable.
- **Inv. Performance → Savings now has Actual/Forecast/Recommendations views**, matching Dividend Tracker's structure. **Actual** gains a period selector (YTD, Previous Year, 1–5 Years, All Time, Custom) scoping interest/principal/YOC%/APY% to that window, alongside the existing always-current "Detail for Last Interest Period" table. **Forecast** (Till EOY / Next 6 Months / Next 12 Months) projects each account's future interest by compounding its current balance forward at its last real interest period's APY% and payment cadence. **Recommendations** ranks your savings accounts by that same APY% and flags idle balances sitting in 0%-yield Cash/Checking accounts, estimating the annual gain from moving them into your best-performing savings account in the same currency — there's no external market of savings accounts to recommend opening, only what you already have.
- **Reports → Cash Flow Forecast now includes Expected Interest Income** — its own KPI card, chart series, and detail table — using the same last-real-interest-period APY%/cadence compounding as Savings' new Forecast view, alongside the existing Expected Dividend Income.

### Fixed
- **Portfolio Analysis → Savings' "Detail for Last Interest Period" table wrapped account names onto two lines** — added `whitespace-nowrap` to that table's Account column and header labels, matching the "Detail" table above it.
- **Monthly bar charts (Dividend Tracker and Savings, both Actual and Forecast) could render a garbled x-axis** — Plotly's default date-axis handling misbehaves when a period has very few distinct months of data (e.g. an EOY forecast with only one projected payment month), showing sub-millisecond tick labels instead of month names. Fixed by explicitly setting the axis to monthly date ticks on all four charts.
- **Savings Forecast didn't convert non-EUR account balances (GBP/USD) to EUR** before labeling projected amounts as such, understating their contribution to the portfolio-wide totals and (once discovered while wiring up Cash Flow Forecast's new Interest Income) would have propagated the same error there too. Fixed at the source (the shared last-interest-period helper now carries each account's FX rate).

## 2026-08-06

### Added
- **Recurring → New/Edit Template no longer lists inactive accounts by default** in the Account and Transfer to Account dropdowns — a "Show inactive" checkbox next to the Account field reveals them again when needed. Editing a template that already points at an inactive account still shows that account regardless of the checkbox, so opening an existing template never blanks out its current selection.

### Fixed
- **TradingView price downloads for GBp/GBX-quoted LSE holdings (Aviva, BAE Systems, Barclays, BP, Legal & General, Lloyds, National Grid, RELX, Rolls-Royce, Shell) were being silently rejected as "suspicious" and skipped** — TradingView returns these in pence, but the stored price is in pounds (via `Securities.Price_Scale`); the TradingView downloader never applied that scale before comparing against the stored price, unlike the Yahoo downloader, so every update looked like a 100× jump and got dropped. All ten securities' recent history was backfilled after the fix.
- **Taiwan Semiconductor Manufacturing Company Limited (2330.TW)'s TradingView price was ~30× too high and getting skipped** — its TradingView symbol/exchange were mismapped to `TSM`/`BCBA`, the Buenos Aires CEDEAR of the NYSE ADR (priced in Argentine Pesos), instead of its actual Taiwan Stock Exchange listing. Corrected to `2330`/`TWSE`, confirmed to match the already-stored data exactly.
- **TradingView price downloads never stored "today" for most exchanges (NYSE, NASDAQ, ATHEX, XETR, EURONEXT, AMEX, CBOE, BME, FWB, TSX, NYMEX) — silently, every day** — the `exchange_calendars` package the downloader uses to tell whether a market is pre-market/open/closed right now was never added to `requirements.txt`, so it always failed to import; the resulting exception was swallowed at debug level and treated as "unknown," which the downloader deliberately skips (to avoid storing TradingView's pre-market garbage as if it were a real close). Added the missing dependency and backfilled today's price everywhere it was missing (~9,700 rows across 304 securities). The failure is now logged at warning level instead of debug, so a regression like this shows up in the scheduler log instead of silently starving every mapped exchange of same-day prices again.

## 2026-08-05

### Added

Portfolio → Sector & Industry tab is now merged into Portfolio Analysis → Sector Weighting**, which drills down two levels: Sector → Industry → Securities, carrying over the old tab's industry-level granularity on top of the fund look-through accuracy Portfolio Analysis already has (an ETF/fund's own value now counts under its actual underlying sector composition, instead of never having a Sector/Industry at all since that data doesn't exist on fund securities). ### Fixed
- **Portfolio Analysis → Bond Quality showed the same credit rating as two separate rows with different casing** (e.g. "BBB" from direct bond holdings and "Bbb" from a fund's look-through ratings) — direct bond holdings hardcode uppercase labels (AAA, AA, A, BBB, BB, B, Below B), while fund look-through ratings came from Yahoo's lowercase snake_case keys (`bbb`, `us_government`, ...) title-cased with no normalization against that convention, so the two paths never merged in the same bucket. Fund-side ratings now map onto the same labels the direct-bond side uses.
- **Portfolio Analysis → Bond Quality's "Uncovered Fund Bond Exposure" bucket counted funds that hold zero bonds** — any ETF/fund lacking a ratings breakdown was bucketed there at full value regardless of whether it actually held any bonds, so e.g. a physical gold/silver ETC (100% commodities, confirmed via its Asset Class Override and a 0% bond allocation from Yahoo) was counted as fully "uncovered bond exposure" instead of having no bond exposure at all. The bucket now excludes funds already known to hold no bonds (an Asset Class Override set to something other than Bonds, or a 0% Yahoo-reported bond allocation).

### Added

BP p.l.c.'s Analyst Target is now €5.95 (was 595.36) with a sane +7.84% upside (was +10683.60%); the other 9 affected securities' stored values were corrected directly.
- **Dividend Tracker → Forecast's Ex-Div and Pay Date columns wrapped onto two lines**, splitting the date at the hyphen (e.g. "2026-08-" / "31") instead of showing it on one line.

The reorder was actually saving correctly — only restoring it on the next render silently failed, because these columns had no explicit ID for the app's column-order memory to match them by.

## 2026-08-03

### Added
- **Every data table in Oikos now has a "Copy to Excel" button** next to Columns — copies the table to the clipboard as tab-separated data, so pasting into Excel or Google Sheets lands in real columns instead of one long line of text. Copies exactly what's currently on screen (sort, search/filter, and visible/hidden columns), same as the table itself. Also replaces the bespoke "Copy" buttons Security Detail → Investment Transactions' Holdings by Account and All Transactions tables already had with the same shared button, so behavior and labeling are now consistent everywhere. The projected total, monthly chart, and per-security table are all bounded to the selected window using each holding's real expected payment dates and frequency (not a naive pro-rata slice of the annual rate) — an annual payer due in March won't show up in an EOY forecast made in October, for example. The table now shows both the period-bounded amount and each security's full annualized rate side by side. Portfolio YOC stays a standard annualized metric regardless of period. "Upcoming payments (next 3 months)" is unchanged — a fixed near-term view independent of the broader period selector.

### Fixed
- **Every data table in the app logged an AG Grid "Theming API and CSS File Themes are both used" console error on every render** — Oikos loads the older CSS-file theming system (`ag-grid.css` / `ag-theme-alpine.css`), but none of the tables told the grid to use it, so newer versions of ag-Grid defaulted to its new Theming API instead, which conflicts with the loaded CSS files. Purely a console-noise issue (styling itself looked fine), fixed by explicitly opting every table into the legacy theme.
- **London Stock Exchange holdings (Aviva, BAE Systems, Barclays, BP, Legal & General, Lloyds, National Grid, RELX, Rolls-Royce, Shell) had Market Value ~100x too high**, inflating Net Worth and making their dividend yield look absurdly low by comparison — the underlying bug that made BP's dividend forecast look wrong. Yahoo reports LSE ordinary-share prices in pence (currency code `GBp`/`GBX`, distinct from `GBP`), but Oikos stored that raw figure as if it were pounds, so BP's price was recorded as "552.10" instead of "5.521". A new `Securities.Price_Scale` column, detected automatically from Yahoo's own currency code, now normalizes every price/quote field for these securities before it's stored (dividend rate, yield, P/E, and market cap were already correctly reported by Yahoo in the major unit, so those are untouched). Existing Historical_Prices, Securities_Quote, and the one affected Investments transaction (BP) were corrected directly; Cost Basis and Holdings were recomputed from the corrected transaction.

## 2026-08-02

### Added
- **X-Ray's Style Box view is now interactive and no longer dumps unclassified funds into one opaque bucket** — click a bar or table row to list the individual securities/accounts behind that category below, with each one's value and % of the category (same click-to-drill-down as Asset Allocation and Sector Weighting). Style Box now also includes Cash & Savings accounts from the active preset as a "Cash" bucket, same as Asset Allocation. A fund with no Morningstar category (and no manual override) is no longer lumped into a single "N/A (no Morningstar category)" pile — it's bucketed by its own dominant asset mix instead (e.g. "Equity Fund (Uncategorized)", "Bond Fund (Uncategorized)", "Allocation Fund (Uncategorized)"), using the same asset-mix data already cached for Asset Allocation; only a fund with no cached composition at all still falls back to "N/A (no data)".
- **X-Ray's Bond Quality and Stock Overlap views are now interactive too** — Bond Quality: click a credit-quality bar/row to list the individual bonds/fund slices behind it below (value, weight % of that quality bucket, duration). Stock Overlap: click a symbol row to list its individual sources below (Direct vs. via each fund, value, and % of portfolio) instead of only the condensed inline summary.
- **X-Ray's Sector Weighting's "Uncovered Fund Exposure" bucket is smaller and more honest** — a fund with a manual Asset Class Override set (e.g. a physical commodity ETC) now uses that override for its sector bucket too, instead of showing as uncovered. A bond-dominant fund with no sector data — sector weighting is a GICS/equity concept Yahoo simply doesn't provide for bond funds — now lands in a distinct "Bonds (No Sector Data)" bucket rather than the same generic "Uncovered Fund Exposure" pile used for funds with no useful classification at all.
- **Security Detail's Overview → My Holdings panel now shows all-time Realized P&L** (same FIFO-based figure as Reports → Inv. Performance → P&L, summed across every account the security has ever been held in), alongside the existing unrealized Gain. Only shown when the security has a realized figure to report.
- **Security Detail's Overview tab now has a Price History chart**, positioned to the left of the Quote panel (which spans both rows) below My Holdings/Security Details, matching the Quicken-style layout — price line, volume bars, and Buy/Sell/Reinvest transaction markers, with the same period selector (3M–All) as the Prices tab (they share the persisted period, so switching one updates the other).
- **Securities Analysis → Portfolio Action Signals is now a full customizable grid** — click a column header to sort, drag headers to reorder, and use the new **Columns** button to show/hide any column (saved server-side, like every other customizable grid in Oikos). It also now carries every field from a security's own Overview tab that wasn't already there: Symbol, Type, Industry, Currency, Exchange; Shares Held, Cost Basis, Avg Cost/Share, Realized P&L; and the full Quote panel (Open, Prev Close, Day High/Low, 52-Week High/Low, Volume, Avg Volume, P/E, Market Cap, Ann Div/Share, Ex-Div Date, Change/% Change) — most hidden by default to keep the table readable, all reachable via Columns. No new backend queries: reuses the same Market Data securities list and all-time P&L data Security Detail's own Overview tab is built from.

### Fixed
- **X-Ray's Sector Weighting showed "Real Estate" and "Realestate" as two separate buckets** — Yahoo's fund sector-weighting data uses the one-word key `realestate` (unlike its other underscore_separated sector keys), which the formatting logic capitalized as "Realestate" instead of "Real Estate", splitting real-estate exposure into a near-duplicate bucket instead of merging with the "Real Estate" GICS sector direct holdings already use.
- **Security Detail Overview's Open, P/E, and Market Cap were blank for every security** — a distressed/penny stock's near-zero earnings produced a Yahoo `trailingPE` value large enough to overflow the `Securities_Quote.Trailing_PE` column's precision. Since every security's quote/sector/industry/dividend/ISIN update for that day shares one database transaction, this single bad value silently aborted the *entire* batch, discarding the day's Yahoo update for all securities rather than just the one at fault — not only Open/P/E/Market Cap, but any field that same run would have refreshed. Trailing P/E and Market Cap are now sanity-clamped to fit their columns (out-of-range values are dropped as unreliable rather than stored or allowed to blow up the transaction) before being written.
- **Saxo PDF import swapped FX Rate and Total (sec. currency) for CFD financing charges** — a pure charge line with no separate trade (e.g. CFD Finance overnight financing) reports the same EUR total across the Booked Amount, Booked Costs, and Total Costs columns. The importer's column-count heuristic mistook these three repeated values for a genuine `[sec amount, conversion rate, EUR amount]` triple and read the real Conversion Rate as if it were the security-currency amount, swapping the two fields (e.g. showing FX Rate 4.91 / Total (sec. currency) 0.87 instead of the correct FX Rate 0.87 / Total (sec. currency) 4.91). The four already-imported transactions from the most recent statement were corrected directly; older imports were checked and were unaffected (that statement's export apparently didn't report the duplicated columns).
- **Dashboard's triggered-alerts panel collapsed itself whenever you navigated away and back** (e.g. clicking an alert to view a security, then Back) — its expand/collapse state was local component state that reset on remount instead of persisting like every other saved UI toggle in the app.

## 2026-08-01

### Added
- **Reports → Inv. Positions has a new X-Ray sub-tab** — a Quicken/Morningstar-style Portfolio X-Ray that looks *through* held ETFs/Mutual Funds into their underlying composition and blends it with direct stock/bond holdings, instead of treating each fund as one opaque line. Six views: True Asset Allocation, Sector Weighting, Style Box (Morningstar-style category), Bond Quality & Duration, Stock Overlap (e.g. "AAPL: 3.2% total — 1.2% direct, 1.1% via VOO, 0.9% via QQQ", built from each fund's top-10 constituents), and Weighted Expense Ratio. Every blended view surfaces an "Uncovered Fund Exposure" bucket for funds with no cached composition data yet, so totals still reconcile instead of silently undercounting. Respects the same account preset as the rest of Inv. Positions.
- **No Morningstar account or subscription required** — fund composition (sector weights, top holdings, asset mix, Morningstar-style category, expense ratio, bond quality/duration) is pulled from Yahoo Finance via `yfinance`, already a dependency, with no new external service and no sharing of actual share counts/holdings with anyone. Cached in two new tables (`Fund_Composition`, `Fund_Top_Holdings`), refreshed monthly by the scheduler or on demand via a new "Download Fund Composition (X-Ray)" button on Market Data → Downloads and Security Detail → Downloads (the latter only shown for ETF/Mutual Fund securities).
- **Security Detail has a new Overview tab**, first in the tab order — a Quicken-style consolidated view with three panels: **My Holdings** (shares held, market value, cost basis, gain/% gain, avg cost/share), **Security Details** (name, symbol, type, industry, market, currency, with an Edit Details shortcut into Setup), and **Quote** (price, change/% change, day open/high/low/prev close, 52-week high/low, volume, avg volume, P/E, market cap, div yield, ann div/share, ex-div date, exchange). Price, dividend, and exchange fields reuse data Oikos already had; day open/high/low, prev close, 52-week range, volume, and avg volume are computed straight from `Historical_Prices` (already downloaded daily for every security's chart — no extra request); only P/E and market cap need the new "Update Security Info" quote data (stored in a new `Securities_Quote` table), since price history alone can't supply those. Any field with no data yet shows "—" rather than erroring.
- **Security Detail has a new Composition & Holdings tab for ETF/Mutual Fund securities** — surfaces that fund's own cached X-Ray look-through data (asset mix, sector weightings, fund details, bond/equity stats, top 10 holdings) right on its detail page, instead of only ever seeing it blended into the portfolio-wide X-Ray. Includes a **Category** selector (Style Box) and an **Asset Class Override** selector (Asset Allocation) to manually reclassify a fund when Yahoo's data can't — e.g. a fund with no Morningstar category, or a physical commodity ETC that Yahoo lumps entirely into a generic "Other" bucket since it has no commodity-specific asset class. X-Ray reflects either override immediately.
- **X-Ray's Bond Quality view can now resolve "Direct / Unrated" bonds to a real credit rating** — a new Static Data → Issuers tab (Name + Moody's/S&P/Fitch ratings + Notes, same pattern as Institutions; covers bond issuers, fund providers, etc., not bonds only) lets you record an issuer and rating, then link it from a security's Setup tab (new "Issuer" field). Rated bonds now bucket under their real rating (AAA/AA/.../Below B) in X-Ray instead of always landing in one undifferentiated pile; unrated/unlinked bonds still fall back to "Direct / Unrated" as before. In passing, Institutions' own Moody's/S&P/Fitch fields — previously free-text, prone to typos against the ratings table they're already foreign-keyed to — are now dropdowns sourced from the same ratings list.

## 2026-07-05

### Fixed
- **Income & Expense report — Realized Investment P&L was wildly wrong**: the old figure could be inflated by hundreds of thousands of euros for accounts that ever sold before a matching buy existed (margin/CFD accounts opening a short position) — the calculation matched sells only against earlier buy lots and silently treated any unmatched portion as free profit. Realized P&L is now computed with a proper signed-lot FIFO simulation that tracks both long and short lots, correctly deferring recognition until a position is actually closed. The same bug, and the same fix, applied to the Investment Tax report's FIFO and LIFO methods.
- **Investment Tax report — WAC (Weighted Average Cost) overstated cost basis**: it recomputed an average from every buy since the position was last fully closed, which double-counted buy value/quantity already consumed by an earlier partial sell within the same still-open position. Now uses a proper running average that blends on every buy and correctly shrinks (without recomputing) as the position is drawn down.
- **Holdings — Simple Avg and FIFO Avg cost per share could be badly wrong**:
  - The database trigger that maintains Holdings guessed "long" vs "short" once from the aggregate lifetime total-buys-vs-total-sells sign, which broke for accounts with negative-quantity adjustment rows (e.g. daily interest-accrual reversals on cash-fund holdings) or any position that went both long and short over its history — in one case making a real holding disappear entirely (quantity computed as zero).
  - Staking-reward entries and corporate-action execution (splits, delistings) never triggered the accurate cost-basis recompute, leaving Holdings with stale figures after those actions.
  - **Simple Avg** was an unweighted mean of purchase prices (so a 0.001-unit buy counted as much as a 100-unit buy), then — after an initial fix — still wrong for any position fully sold and later rebought, since it kept blending in cost basis from units no longer held. It's now a running average that resets to zero whenever a position closes out exactly, matching FIFO Avg except where lot order genuinely matters (observed: a Bitcoin holding sold off entirely in 2017 and 2020 and rebought from 2025 onward now correctly shows ~€86,470 instead of ~€55,000 or ~€2,100 from the two earlier, still-wrong versions).
- **Income & Expense KPIs didn't reconcile**: "Savings by Investments" silently included realized trading P&L while "Net Savings" excluded it, so the two could disagree by tens of thousands of euros with no visible explanation. Realized P&L is now excluded from both and shown as its own clearly-labeled "Realized Investment P&L" figure instead.
- **Recurring transfer templates could silently drop the mirrored transaction**: three of four code paths that generate/confirm template-driven transfers never created the destination-account leg or linked the two rows via a shared transfer ID. All four now share the same logic; the one real affected transaction found in the data was repaired.
- **Investments → Holdings**: clicking a ticker or security name silently did nothing (a scoping bug meant the click handler called an undefined function). Now correctly opens the security's detail page.
- **Investments → Transactions**: editing a transaction linked to an inactive account showed a blank Account field, since the edit form's account dropdown excluded inactive accounts — could look like an orphaned/unlinked record. The dropdown now always includes the transaction's actual account, active or not.
- **Multi-currency amounts showed the wrong currency symbol**: Price/Commission/Total and account balances in Investments and Cash Register always showed the reporting-currency symbol (typically €) regardless of the security's or account's real currency — e.g. a USD stock's price, or a USD account's balance, both displayed with "€". These now show the correct native currency throughout (grids, page subtitles, the credit-card summary bar, and cross-account search results).
- Fixed a pandas `FutureWarning` about DataFrame concatenation dtype handling in the realized-P&L calculation (cosmetic — no behavior change).
